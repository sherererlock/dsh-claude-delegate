关键代码

package.json 决定三件事：装什么、怎么被加载、发布哪些文件。下面只留相关字段。

package.json（节选）
{
  "type": "module",
  "main": "lib/index.js",
  "types": "lib/types/index.d.ts",
  "exports": {
    ".": {
      "types": "./lib/types/index.d.ts",
      "default": "./lib/index.js"
    },
    "./client": {
      "types": "./lib/types/client/index.d.ts",
      "default": "./lib/client.js"
    }
  },
  "files": [
    "lib",
    "lib/client.js",
    "cordis.patch.yml",
    "CHANGELOG.md"
  ],
  "dsh": {
    "bundle": {
      "patch": "./cordis.patch.yml"
    },
    "client": {
      "platform": "web",
      "inject": [
        "@deepseek-ai/dsh-client-runtime",
        "@deepseek-ai/dsh-client-connection",
        "@deepseek-ai/dsh-client-ui-conversation"
      ]
    }
  }
}

dsh.bundle.patch 指向的 cordis.patch.yml 是安装时的接线清单：dsh plugin add 把它并进 profile 的 dsh.profile.bundles，id 要用稳定字符串。

两套 tsconfig 服务于两个运行环境，不要合成一套。

配置 关键项 产出 用途
tsconfig.json module: NodeNext、lib: ES2022、outDir: lib、排除 src/client lib/*.js + lib/types/** 宿主侧，Node 直接加载
tsconfig.client.json module: ESNext、moduleResolution: Bundler、lib: ES2022 + DOM、jsx: react-jsx、emitDeclarationOnly: true 仅 lib/types/client/** 给 esbuild 打包的客户端类型

npm run build 的顺序：tsc -p tsconfig.json → tsc -p tsconfig.client.json → node scripts/build-client.mjs → node scripts/assert-artifacts.mjs。前两步任何一步非零退出，后面都不会跑。

客户端 bundle 的加载方式与普通库不同。DSH shell 按 classic script 加载它，整个文件必须是一次 window.__ModuleLoader__.load({ id, factory }) 调用，id 必须等于包名。factory(require) 里只有 shell 的 seed 模块可解析，其余依赖必须打进产物。esbuild 生成 CJS factory，banner/footer 负责套外壳。

scripts/build-client.mjs（节选）
const SEED_MODULES = [
  'react', 'react/jsx-runtime', 'react-dom', 'react-dom/client',
  '@deepseek-ai/cordis', '@deepseek-ai/dsh-client-ui-slots',
  // ... 其余由 shell 提供的模块
]

const banner = [
  `window.__ModuleLoader__.load({`,
  `\tid: ${JSON.stringify(pkg.name)},`,
  `\tfactory: (require) => {`,
  `var module = { exports: {} };`,
  `var exports = module.exports;`,
  '',
].join('\n')

await build({
  entryPoints: [join(root, 'src', 'client', 'index.ts')],
  outfile,
  bundle: true,
  format: 'cjs',
  platform: 'browser',
  external: SEED_MODULES,
  banner: { js: banner },
  footer: { js: footer },
})

// 产物必须满足 shell 的加载契约
if (!text.startsWith('window.__ModuleLoader__.load({')) throw new Error(...)
if (!text.includes(`id: ${JSON.stringify(pkg.name)}`)) throw new Error(...)

三个实测坑

  1. 全局 TypeScript 6 与本项目 ^5.4.5 不兼容。本机全局 typescript 是 6.0.3；TS 6 把 baseUrl 的弃用从警告升级成 error（TS5101），tsc 直接退出。构建和类型检查都用项目自己的 node_modules/typescript：npm run build、npm run typecheck 会自动用本地版本，不要直接调用全局 tsc。
  2. tsc 类型报错仍会产出 JS。noEmitOnError 默认是 false，所以 lib/index.js 存在不代表编译成功，assert-artifacts 通过也不代表类型正确——它只查文件是否存在、大小是否为 0。判断标准是 tsc 的退出码和错误输出；发布前单独跑一次 npm run typecheck。
  3. peer 范围是强制检查，不是文档约定。dsh plugin add 会读 peerDependencies；存在 engines.dsh 时以它为准。不兼容会直接拒绝安装，并打印 allow-version ... --accept-risk 豁免命令，错误信息写明可能崩溃或丢数据。实测把 peer 写成 >=99.0.0，安装被拒。devDependencies 不参与兼容判断；peerDependenciesMeta.optional 的 peer（本项目的 react 与客户端 primitives）缺失时不阻塞。

版本比较把 prerelease 纳入，0.2.2-rc.5 按实际次序比较；不要直接套 npm 默认的 prerelease 排除规则。细节见练习 6.2。

安装与调试

构建成功后，用测试 profile 安装一次。按下面四条命令走一遍，能区分配置层、模块加载和运行期的问题。

bash
npm run build
dsh plugin --profile smoke add E:/path/to/your-plugin
dsh --profile smoke --dump-config
dsh --profile smoke

--dump-config 只证明配置层组合，不 import 模块。要证明模块能加载，必须实际启动一次。新 profile 默认只有 @deepseek-ai/dsh-base，没有 app；直接启动会静默挂起。先把 @deepseek-ai/dsh-headless（或 web）加进 dsh.profile.bundles，再启动。

自测

Q1. lib/index.js 已经生成，能说明 tsc 编译成功吗？
参考答案
不能。noEmitOnError 默认 false，类型错误仍会产出 JS。看退出码和错误输出；发布前跑 npm run typecheck。assert-artifacts 只查文件存在和大小，不查类型。
Q2. 为什么宿主和客户端要两套 tsconfig？
参考答案
运行环境不同。宿主跑在 Node，用 NodeNext、ES2022、无 DOM；客户端跑在浏览器，用 ESNext + Bundler、DOM、react-jsx。客户端 tsc 只出声明，JS 交给 esbuild 打成单个 classic script。混用会让 DOM 类型漏进宿主，或让客户端拿到 Node 类型。
Q3. files 里漏了 cordis.patch.yml 会怎样？
参考答案
npm 包不带这个文件，dsh.bundle.patch 指向的文件不存在；dsh plugin add 会把包当普通依赖安装并警告，插件不会被自动接线。安装后 --dump-config 里看不到条目。
Q4. dsh plugin add 遇到不兼容的 peer 会警告后继续吗？
参考答案
不会。peer 是强制检查，安装直接失败，并打印 allow-version ... --accept-risk 豁免命令。只有明确知道风险时才用豁免。

本节最佳实践

  • 构建链 fail fast：产物断言放最后，缺文件直接非零退出；不要用 || true 吞掉。
  • files 用白名单，只发运行所需；exports 同时给 types 和 default，客户端子路径单独列。
  • 版本兼容只看 engines.dsh（存在时）和 @deepseek-ai/dsh* peer；prerelease 纳入比较；不要用 devDependencies 判断。
  • 类型检查和构建分开跑：npm run typecheck 不产 JS，npm run build 产 JS；CI 两个都跑。
  • 安装验证用全新 profile：先 --dump-config 确认配置层，再 boot 确认模块加载；本地路径安装不联网，适合反复试。
  • 客户端 bundle 的 id 必须等于包名，外部依赖只能来自 shell seed 表；构建脚本已经断言，别用 --external:* 绕过。

完成标志

npm run build 通过，assert-artifacts 覆盖新增模块；本地 dsh plugin --profile <test> add <path> 成功，--dump-config 出现条目，启动 profile 能加载；能复现并规避三个坑：全局 TS6、tsc 报错仍产 JS、peer 强制检查。
