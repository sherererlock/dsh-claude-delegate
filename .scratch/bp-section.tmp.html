REFERENCE 最佳实践对照

把散在阶段里的「官方推荐 vs 本项目做法」汇总成一张检查表。毕业项目开工前过一遍，分清哪些照官方写、哪些只在这个仓库成立。

9 组官方最佳实践

按官方文档的主题分组。每组只留一句核心推荐；细讲在各阶段正文，出处以正文标注为准。

  1. 01Cordis 插件契约与生命周期导出 name、inject、apply；所有注册都是可逆副作用；定时器、连接、watcher 这类 Cordis 不管理的资源包进 ctx.effect()；依赖用 inject 表达，不手排启动顺序。出处：cordis-tutorial/01–03 · cordis-primer
  2. 02服务依赖：硬依赖与可选依赖缺了就不能工作，写进 inject；缺了还能降级，不写 inject，在使用处用 ctx.get(name) 探测。inject 在运行中持续跟踪，服务消失会卸载依赖方。出处：cordis-tutorial/03 · cordis-api/context
  3. 03配置导出同名 Config 接口和 schemastery schema；默认值与约束都写进 schema，非法配置在加载时 FAILED；patch 按 id 替换整个 config，不是深合并。出处：cordis-tutorial/05 · basic/config · architecture（Profile 与组合包）
  4. 04工具注册第一方工具用 defineTool 推导并校验 args；output.schema 校验返回值，output.render 只做模型可见内容；parameters 用统一 JSON value DSL，对象显式写 additionalProperties；execute 转发 exec.signal；timeoutMs 是正有限值。出处：basic/tool · subsystems/tools · extension-cookbook
  5. 05技能运行时技能用 ctx.skills.register，随插件卸载；用户可编辑的内容优先放文件系统 skill，随包固定的才用运行时注册。出处：subsystems/skills
  6. 06后台作业用 ctx.jobs.start 生产，run 同步返回 hooks；输出用 handle.append，结果用 JobOutcome.result；观察者用 readAt 非消耗读，模型用 read；取消用 kill(id, caller, reason)；新 kind 用声明合并扩展 JobKindMap。出处：subsystems/jobs
  7. 07客户端在 package.json 声明 dsh.client，导出 ./client；dsh.client.inject 只是信息性依赖边，模块请求用 external；slot 用 ctx.slots.inject 包 ctx.slots.register；Remote 方法用 @Remote 并走生成契约；bundle 是一次 __ModuleLoader__.load({ id, factory }) 调用。出处：subsystems/client-modules · slots · api-gateway
  8. 08会话、持久化、子代理DSH 的持久化是 SessionEvent 日志，跨重载的事实进会话事件；当前模型用 agent.model.current()；委派给另一个 agent 产品用 ctx.subagents 提供方注册表。出处：subsystems/persistence · session-projection · subagent
  9. 09构建与发布package.json 的 type / main / types / exports 齐全，peer 与 dev 成对；schemastery 放 dependencies；files 精确；每个 lib/client.js 必须产出；可替换能力才拆包，按 Service Definition / Provider / Consumer 三角色组织。出处：adding-a-package · publish · architecture（能力 seam）

8 个灰色地带

官方 docs 没写清楚、只能从包 README、类型声明或运行时反推的地方。学的是「怎么找契约」，不是背结论。

编号灰色地带事实来源学习者怎么对待
G1window.__ModuleLoader__.load 是客户端 bundle 的运行时契约，但 docs/ 全量没有这个字样。官方包 dsh-client-modules README、src/client/manifest.ts JSDoc、scripts/build-client.mjs。把「id 等于包名、factory 只 require seed 表」当硬契约；读包 README 和源码。
G2客户端 ctx.jobs 服务（watchRows / observe / kill）没有 API 文档。config-catalog 只列 dsh-client-ui-jobs 包名；src/client/types.ts:36-68 是逆向形状。优先 ctx.remote.job.list/follow/kill；读内部服务要写兼容层和失败提示。
G3agent.model.current() 是公开类型，但没有 docs 章节。@deepseek-ai/dsh-agent 的 runtime-types.d.ts:47-63、model-selection.d.ts:15-20。记住 owning domain service 优先；类型声明也是官方契约。
G4sessionProjections.stateOf(session,key) 在包里标 @deprecated，docs 页面不列。包内 .d.ts:225-227；首次读会 logger.warn；upgrade-guide/v0.2.1-rc.2 有迁移说明。用 agent.model.current() 或 awaited handle.stateOf(session)；不要因为「现在还能跑」继续用。
G5仓外插件的 Typert 生成没有文档路径。api-gateway 的严格生成流水线只描述仓内构建。SRC 参数名当公开 API，写契约测试；能进仓就走严格生成。
G6dsh.client.inject 的语义：JSDoc 说信息性，client-modules 说 package edges。DshClientManifest JSDoc 与 client-modules §wire 两处措辞不一致。服务注入看 export const inject；模块请求看 external。
G7ctx.jobs.kill 是否通知模型。jobs 文档说 owner agent 仍收到完成通知；本项目 tracker.ts:1-12 说相反。以当前文档为准；升级 DSH 后实测一次，再决定是否保留自建取消。
G8Cordis 4.x 没有 optional-inject 对象形式。官方 docs 只推荐「硬依赖 inject / 可选 ctx.get」；src/index.ts:21-26、CHANGELOG.md:42-43 记录对象形式会死锁。硬依赖写 inject，可选依赖用 ctx.get；不要发明 { required, optional }。

三张清单

读完教程后按这三张清单复查自己的代码。

可以照抄

  1. 插件骨架：name / inject / apply，配置用同名接口 + schemastery。
  2. 可选依赖：ctx.get('service')，不要写进 inject。
  3. 工具四段式：parameters / output.schema / output.render / execute，加 presentCall。
  4. exec.signal 转发 + timeoutMs 声明；注意 0 值和 per-call 语义。
  5. 后台作业生产方：jobs.start({ kind, label, owner: sessionId, run })，run 同步返回 { cancel, done }，推流用 handle.append，结果用 JobOutcome.result。
  6. 客户端 slot 贡献：ctx.slots.inject(key, () => ctx.slots.register({ name, id, order }, Component))。
  7. 客户端清单：dsh.client.platform: 'web' + exports["./client"]。
  8. 组合包：dsh.bundle.patch + cordis.patch.yml 的 insert 行；patch 只写用户大概率保留的默认值。
  9. 构建断言：缺 lib/client.js 直接失败；新增模块时同步更新产物清单。
  10. 运行时技能：ctx.skills.register + source: 'runtime'，随插件安装/卸载。

不要照抄

不要照抄官方推荐原因
sessionProjections.stateOf(session,key)agent.model.current() 或 awaited handle.stateOf(session)已 deprecated，未来会移除
args: any / value: any + 无 required 的 output schemadefineTool 推断 + 完整 canonical schema放弃校验等于放弃工具契约
permissionMode: z.string() / effort: z.string()z.union([...枚举]) + .min()配置错误应在加载时响亮失败
无条件 timeoutMs: config.timeoutMs正有限值或省略；per-call 语义写清0 值会让注册失败；前台大值无效
自建文本输出环 + 自建取消（仅后台 job）ctx.jobs.readAt + ctx.jobs.kill / ctx.remote.job.kill官方已提供非消耗读与通知语义
dsh.client.inject 当依赖注入用Cordis inject 用服务名；模块请求用 dsh.client.external两者语义不同
jobs: any + 不声明 JobKindMap类型声明合并 + 窄接口失去编译期保护
手工样式注入不清理非 Cordis 资源包 ctx.effect卸载 / HMR 后残留
config.subagents 当 DSH 子代理DSH 子代理用 ctx.subagents同名不同物
README 说 subagents 是工具参数以 parameters 源码为准文档与实现不一致

  7. 两阶段超时警告、错误文案映射、GBK 回退、taskkill /T /F 进程树清理。

  10. fork 历史与 CHANGELOG 0.1–0.8 的演进。
